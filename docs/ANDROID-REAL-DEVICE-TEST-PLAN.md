# Android 真机测试计划（v1.0）

> 制定日期：2026-11-03 · 适用版本：`com.photomgm.app` **1.3.2 (versionCode 6)** 及之后
> 当前接入设备：vivo V2232A（`10AD2G1FLK001AQ`）· Android 16 / API 36 · arm64-v8a
> 一句话：**这份计划的任务不是"点一遍看看"，而是给 T11 第二提交（导出段迁移）发通行证 ——
> 判据是"S1/S2 缺陷为 0 且导出产物与基线逐字节一致"，不是"没崩"。**

## 1. 测试范围与目标

### 1.1 为什么要做这一轮（不是通用验收）

三件事把"必须真机跑一遍"变成了前置条件：

| 事实 | 后果 |
| --- | --- |
| **T11 第一提交已合入**（`AppViewModel` 交出分析/调整/设置，新增 `core/` 组装根） | 10 个 Robolectric 单测全绿，但它们跑在 JVM 上。`core/` 里有 4 处只有真机才暴露的行为（协程调度、SAF、SharedPreferences 落盘时序、MediaStore 权限） |
| **计划 §17.5 明确规定**：第二提交要重写 ZIP 写入，而这段的自动化覆盖只有 `ExportGateTest` 三条（验门禁，不验 ZIP 内容） | 没有真机跑出的"产物正确"证据，第二提交等于在最高风险路径上盲改 |
| **P1-3 未结案**：缺/有 `ACCESS_MEDIA_LOCATION` 时 GPS 曾呈"部分剥离"（9/65 张先丢） | 去重判定依赖 GPS，而 R12 已实测过一次"把两张不同照片并成一张并永久删除" |

### 1.2 范围

| 在范围内 | 不在范围内（另有归属） |
| --- | --- |
| 安装/升级/卸载、冷热启动、后台驻留 | 视觉还原度与设计稿比对（`docs/UI-REDESIGN.md`） |
| 12 项核心功能清单（含 T11 新增组装根的每条路径） | 跨端产物一致性判定方法本身（`docs/golden/README.md` 已有 V1~V4 口径） |
| 权限申请/拒绝/撤销/降级、系统版本与 ROM 兼容性 | 桌面端功能（桌面黄金样本已覆盖） |
| 离线可用性、云盘目录写入、时区/校时漂移 | 发布签名、渠道包、灰度策略 |
| 启动/扫描/导出耗时与内存、连续循环稳定性 | 长期功耗与发热曲线（需专用仪器） |
| 异常中断后的恢复：杀进程、断电、空间不足、照片被删 | 多语言（当前仅中文） |

### 1.3 目标（可判定的四条）

1. **G1 功能**：12 项清单全绿 —— 当前 `docs/REFACTOR-EXECUTION-PLAN.md` §17.3 第 4 条待办，本计划跑完即结案。
2. **G2 产物**：单次导出 ZIP 与 `docs/golden/android-baseline.json` 比对 **0 差异**；同版本双跑（V2）**0 差异**；导出照片与素材**逐字节相同**。
3. **G3 稳定**：6 类用例执行期间 **崩溃 0 / ANR 0**；连续 20 轮「分析 → 导出」无 OOM、无内存单调上升。
4. **G4 权限**：授予 `ACCESS_MEDIA_LOCATION` 后 GPS **100% 保留**（P1-3 的"部分剥离"不再复现）；未授予时降级提示**可见且文案正确**。

## 3. 执行顺序

依赖关系决定顺序，不能自由调换：

```
批次 0 · 环境准备（10 min）
   └─ 批次 1 · 安装与启动 IN（15 min）
        └─ 批次 2 · 权限 PE-01~03（10 min）   ← 不授权后面全跑不了
             └─ 批次 3 · 核心功能 CO（90 min）★ 主战场，12 项清单在此
                  ├─ 批次 4 · 网络与弱网 NE（30 min）
                  ├─ 批次 5 · 性能与稳定性 PF（60 min）
                  └─ 批次 6 · 异常与恢复 RC（60 min）
                       └─ 批次 7 · 兼容性 PE-06~08（按设备到位情况追加）
```

| 批次 | 内容 | 依赖 | 预估 | 中途可中断 |
| --- | --- | --- | --- | --- |
| 0 | 重装被测包、推素材、清缓存、记版本指纹 | — | 10 min | 否 |
| 1 | IN-01~05 | 0 | 15 min | 否（IN-01 之后状态是后续基线） |
| 2 | PE-01~03（首授权、拒媒体、拒位置） | 1 | 10 min | 否 |
| 3 | CO-01~18 | 2 | 90 min | **是**（CO-01/02/03 之后每步可断点） |
| 4 | NE-01~04 | 3 | 30 min | 是 |
| 5 | PF-01~06 | 3 | 60 min | 是（PF-06 需连续） |
| 6 | RC-01~08 | 3 | 60 min | 是 |
| 7 | PE-06~08 与补测机型 | 3~6 | 按机型 | 是 |

**每批次开始前的重置动作**（否则结果不可复现）：

```bash
export ANDROID_HOME="D:/Android/sdk"; ADB="D:/Android/sdk/platform-tools/adb.exe"
"$ADB" shell pm clear com.photomgm.app          # 清数据（会清掉设置/缓存/人工调整）
"$ADB" shell am force-stop com.photomgm.app      # 确保冷启
```
> `pm clear` 之后**权限也会被重置**，权限类用例（PE）必须紧跟重装之后跑，不能跳。

### 4.4 网络与弱网（TC-NE）

### 7.2 连带确认的三件事（不在清单里，但顺手验了）

1. **改日期会重新粗筛**：`2026-11-03`（今天）时照片 0 张，改到 `2026-08-14` 立刻扫出 68 张 —— 日期是文件名粗筛的基准，符合预期。
2. **重新分析会清空人工调整**：⑫ 的清缓存重解析之后，`photo_override` 与 `photo_marked` 都变空、角标消失。核对源码 `AnalysisPipeline` 第 106 行 `session.clearManual()`，与旧版 `store.overrideMap = emptyMap()` 同义 —— **是既有产品语义，不是回归**。
3. **待复查事件本来就不挂照片**：全列表第一屏事件卡都是 0 张，一度怀疑"照片没进事件"；切到「正常」标签后是 1 张 / 2 张 —— 0 张的是 27 条待复查事件（分类不明确），不是缺陷。

### 7.3 对 §2.3 那条"素材别放 DCIM/Camera"的修正

原文说：素材放 `DCIM/Camera` 会把真实相册一起扫进来，导出照片数永远对不上基线。
**实测不成立**：粗筛只按**文件名日期**过滤，真实相册照片文件名不是 `IMG_20260814_*`，一张都没混进来
（MediaStore 里 `DCIM/Camera` 下匹配 `IMG_20260814%` 的恰好 68 条，界面也是 68）。
真正要注意的是 `Pictures/pmgolden` 这类**历史测试目录**里同名前缀的残留 —— 本轮它在 MediaStore 里另有 68 条，
只有"源目录只选 `DCIM/Camera`"才保证不串。故该条改为：
**素材可以放 DCIM/Camera，但源目录必须只勾选它；同名前缀的历史测试目录要先清。**
