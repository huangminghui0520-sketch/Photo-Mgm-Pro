## 一、定位与适用范围

### 1.1 这份文档解决什么问题

不是"界面长什么样"，而是**"为什么这样长"**，以及在无人专职做设计的项目里，
**哪些决策必须写死成代码、哪些可以先留白**。所以本文的每一节都带两个东西：结论 + 依据。
没有依据的视觉偏好不写进来。

### 1.2 适用

| 维度 | 范围 |
|---|---|
| 平台 | Windows 10 / 11 x64（不做 Win7、不做 macOS/Linux） |
| 输入设备 | 鼠标 + 键盘（滚轮、右键、拖拽、组合键） |
| 屏幕 | 1366×768 ~ 3840×2160，缩放 100%~200% |
| 使用场景 | 内业办公室，室内恒定光，连续使用 1–3 小时/批次，单批 200–1000 张照片 |
| 用户 | 巡查内业岗，熟悉 Excel，不熟悉命令行；同一批数据也可能在 Android 版上处理 |

### 1.3 不适用（明确排除，避免后续争论）

- **触摸 / 平板 / 手写笔**：命中区按鼠标 36 dp 设计，不满足 48 dp 触摸标准。
- **深色模式**：`UI-REDESIGN §2.3` 的深色令牌已备好但 U1 不接；见 §9.4。
- **手机尺寸**（<798 dp 宽的多栏形态）：窄到该档时右栏退化为覆盖层，但这不是移动端布局。
- **品牌营销页 / 引导页 / 启动闪屏**：工具型软件，无此需求。

## 二、设计原则

四条，全部由场景推导，不是通用美学口号。

| # | 原则 | 推导 | 落到哪里 |
|---|---|---|---|
| P1 | **照片是主角，界面是衬底** | 用户的注意力 90% 在照片上，任何 UI 装饰都在抢注意力 | 中性底取巡查场景本身（护栏灰/沥青灰），只有主操作和安全橙出现饱和色 |
| P2 | **一屏之内给出全部判断依据** | 内业岗要边看照片边核对桩号/时间，切页 = 丢上下文 | 三栏常驻，不做 Tab 切换；折叠可逆，不隐藏信息 |
| P3 | **每个"不能点"都要说明原因** | 上一版最大投诉是"按钮点了没反应" | 按钮禁用必须带 tooltip；`canExport` 等判据来自 AppState，不在 UI 重算 |
| P4 | **动效克制到几乎为零** | 户外/连续作业，动效只延迟反馈 | 只保留展开收起 200ms、Sheet 220ms；其余 0ms |

## 三、视觉风格

### 3.1 风格签名（六维，沿用 Android 版已定稿的结论）

| 维度 | 取值 | 含义 |
|---|---|---|
| `ground` | light | 室内办公，强光下可读优先 |
| `typeVoice` | sans-cool | 工具型界面，无衬线 |
| `imageWorld` | photo | 巡查实拍照片是主要视觉资产 |
| `layoutLogic` | rail + list-detail | 左栏常驻锚点 + 中列表 / 右详情 |
| `colorStrategy` | tri-role | canvas / surface / world 三级底 + 单一主操作色 + 状态三色 |
| `motionVoice` | still | 仅展开、Sheet、双击缩放 |

### 3.2 色彩（值来自脚本实测，不是手调）

| 令牌 | 值 | 角色 | 实测对比度 |
|---|---|---|---|
| `canvas` | `#F1F4F0` | 页面底 | — |
| `surface` | `#FBFCFA` | 面板/卡片底 | — |
| `surface2` | `#E7ECE6` | 次级底、缩略图占位、按压态 | — |
| `world` | `#222B29` | 顶栏、状态栏 | — |
| `ink` | `#17201D` | 主文字 | 15.02:1 canvas |
| `dim` | `#5C6663` | 次级文字（实色） | 5.36:1 canvas / 4.96:1 surface2 |
| `accentBrand` | `#F0560A` | **仅**装饰色块/轨线/≥19sp 大字 | 3.14:1（**不可用于正文**） |
| `accentText` | `#B94208` | 任何橙色**文字** | 4.92:1 |
| `accentFill` | `#CE4A09` | 主按钮**填充**（白字在其上） | 4.56:1 |
| `ok` / `warn` / `bad` | `#2B7349` / `#8D5C17` / `#B6392C` | 已分类 / 待复查 / 未识别 | 5.19 / 5.15 / 5.25 : 1 |

**三条不可协商的规则**（破坏即掉到 WCAG AA 以下，代码注释里也钉了）：

1. 橙色拆三个角色。`#F0560A` 在画布上只有 3.14:1 —— 够图形线（3.0）、**不够正文线（4.5）**。
2. 状态角标底色透明度 **6%**（原型写的 12% 实测只有 4.2:1）。实现令牌：`okWash/warnWash/badWash`。
3. 次级文字用实色，不用 `rgba(...)`；半透明在 `canvas` 上勉强达标，落 `surface2` 就破线。

### 3.3 排版

| 层级 | 桌面 | Android | 用途 |
|---|---|---|---|
| display | 26 / 600 | 26 | 空状态大标题 |
| headline | 19 / 600 | 19 | 分区标题 |
| title | 15 / 500 | 15 | 卡片标题、列表主行 |
| body | 14 / 400 | 13（bodySmall） | 正文 |
| bodySmall | 13 / 400 | 12→13 | 副信息、桩号、时间 |
| label | 12 / 500 | 11 | 徽章、chip |
| **numeric** | 14 / **tnum** | 缺失 | 桩号、日期、张数、百分比 |

**桌面与手机的两处有意差异**：① 绝对字号上调 1–2sp（手机 35cm、桌面 60cm，同 sp 角直径小 40%）；
② 补 `numeric` 等宽数字档 —— 列表里 `K138+700` / `K139+100` 不对齐会有明显参差感。

字体族**不写死**，用平台默认（U0 实测中文渲染正常）。理由：Windows 缺字体时 UI 会整体退回丑陋回退字体，
而打包自带一份中文字体要 +8MB；这个取舍留到 M7-prod 定，U1 不做。

### 3.4 形状与间距

| 令牌 | 值 | 说明 |
|---|---|---|
| `space.xs/s/m/l/xl` | 4 / 8 / 14 / 20 / 32 | 统一阶梯，**禁止裸写 6.dp / 10.dp** |
| `radius.control` | 8 | chip、输入框、缩略图格 |
| `radius.card` | 12 | 事件卡、设置卡 |
| `radius.shell` | 20 | Sheet、覆盖层 |
| `hit.min` | 36 | 鼠标命中下限（触摸是 48，本产品不做触摸） |
| `topBar` / `statusBar` | 52 / 30 | 顶栏 / 状态栏高度 |

## 四、布局结构

### 4.1 窗口骨架（四段式）

```
┌──────────────────────────────────────────────────────────────┐
│ TopBar 52   [☰] 巡查日期 2026-11-01 · 已就绪   事件7 照片8 未匹配8 │  world 底
├────────┬─────────────────────────────────┬───────────────────┤
│ 左栏   │ 中栏 · 照片网格                  │ 右栏 · 事件        │
│ 300/56 │ flexible ≥420                   │ 320~360           │
│ surface│ canvas                          │ surface           │
│        │ ┌──────┬──────┬──────┐          │ ┌───────────────┐ │
│ 源目录 │ │ 4:3  │ 4:3  │ 4:3  │          │ │ ① 事件类型 3张 │ │
│ 日志   │ ├──────┼──────┼──────┤          │ └───────────────┘ │
│ 设置   │ │ 4:3  │ 4:3  │ 4:3  │          │ ┌───────────────┐ │
│        │ └──────┴──────┴──────┘          │ │ ② …           │ │
├────────┴─────────────────────────────────┴───────────────────┤
│ StatusBar 30  分析完成 · 可预览与导出      匹配 0/8 无 GPS 8   │  world 底
└──────────────────────────────────────────────────────────────┘
```

**为什么顶栏不写应用名**：系统标题栏已经写了。重复一遍等于花 52 dp 高度说废话；
那块位置改成「正在处理哪一天」—— 这才是巡查员每次要确认的信息。

**为什么状态栏常驻**：进度、提示、计数三类信息在任何一屏都可能需要，做进弹窗就要打断操作。

### 4.2 三栏宽度分配（唯一实现 `Workspace.metrics()`）

| 档 | 窗宽（内容区 dp） | 左栏 | 中栏 | 右栏 | 列数 |
|---|---|---|---|---|---|
| W1 宽 | ≥1440 | 300 可展开 | flexible | 360 | 4~8 |
| W2 中 | 1042~1439 | **可展开**（300）或折叠（56） | ≥420 | 320~360 | 2~4 |
| W3 窄 | 798~1041 | **强制折叠** 56 | ≥420 | 320~360 | 2~4 |
| W4 极窄 | <798 | 56 | 独占 | **0（覆盖层）** | 1~4 |

- 允许展开的临界值 = `300 + 420 + 320 + 2×1 = 1042`；这是算术结果，不是感觉。
- 窗口窄于 1042 时，**展开按钮置灰并说明原因**（P3），不做"点了没反应"。
- 中栏列数 = `⌊(中栏宽 + 4) / (160 + 4)⌋`，夹在 `[1, 8]`。420 → 2 列，324 以下 → 1 列。

### 4.3 窗口尺寸（与 `WindowGeometry.kt` 一一对应）

| 项 | 值 |
|---|---|
| 默认（期望） | 1440×900 |
| 最小 | **900×540** |
| 首次启动 | `min(期望, round(工作区×0.9))` 再夹进 `[最小, 工作区]`，居中 |
| 二次启动 | 恢复记忆值，仅做合法性修正（低于最小抬高 / 超出工作区居中） |
| 记忆单位 | **dp**，不是物理像素 |
| 实测（1366×768@125%） | 工作区 1093×574 → 开出 **984×540** |

> 640 高度不可用：1093×574 的工作区里，640 比可用高度还高 66 dp，窗口下边缘被屏幕裁掉。
> 另注意 `574×0.9 = 517 < 540`，clamp 的上下界会交叉 —— 直接 `coerceIn` 会抛异常崩在启动阶段。

### 4.4 高度与滚动

- 顶栏 52 + 状态栏 30 固定，中间区域吃剩余高度（最小窗下 ≈ 458 dp）。
- 三栏**各自独立滚动**，滚动条只在悬停/Hover 时显形（细 6 dp，宽 3 dp 可点）。
- 540 高度下中栏约显示 2.5 行缩略图 —— 这是可接受的，因为列数已经降到 2~3 保证单格够大。

## 五、页面与组件清单

### 5.1 页面（P0，首版必须有）

| ID | 页面 | 形态 | 数据来源 | 关键约束 |
|---|---|---|---|---|
| PG-1 | 主工作区 | 主窗口（三栏） | `AppState` 全量 | 见 §4 |
| PG-2 | 设置 | 右侧 Sheet（宽 380） | `settings.*` | 改动即存，无"确定"按钮 |
| PG-3 | 日志导入 | 左栏内联 + 拖拽热区 | `logText` / `parsed` | 未识别行必须显式提示条数 |
| PG-4 | 导出确认 | 模态 `AppSheet` | `ledger` / `settings.outputDir` | 未设输出目录时按钮禁用 + 说明 |
| PG-5 | 导出进度 | 顶栏下方细进度条 + 状态栏文字 | `exportProgress` | **可取消**，取消后保留已导出部分 |
| PG-6 | 导出结果 | Sheet，含失败明细表 | `lastExport` | 失败项可复制路径；续传语义要写清 |
| PG-7 | 大图预览 | 全窗覆盖层 | `photos[id]` | Esc 关闭；左右键切换；双击进出 |
| PG-8 | 空态 / 错误态 | 中栏占位 / 顶部横幅 | `status` / `error` | 错误文案可复制给工程师 |

### 5.2 组件库

**Atoms**：`Btn`（primary/ghost/danger）、`Field`、`Chip`（状态四色）、`Badge`（计数）、`SeqBadge`（事件序号）、`Divider`、`Icon`（20 dp 线性）。

**Molecules**：
- `PhotoTile` — 4:3 缩略图 + 文件名 + 拍摄时间；状态：default / hover / selected（2.5 dp 边框）/ derived（`_original` 角标）/ broken（解码失败占位）。
- `EventCard` — 序号 + 事件类型 + 桩号 + 时间区间 + 照片数徽章 + 提示行；状态：default / hover / dropTarget / pending（无时间事件）/ 无照片。
- `RailSection` — 标题 + 计数 + 内容，左栏三段复用。
- `ProgressLine` — 2 dp 高，`world` 底 + `accentBrand` 前景，无缓动动画。

**Organisms**：`TopBar`、`SourceRail`、`PhotoGrid`（虚拟滚动）、`EventPanel`、`StatusBar`、`AppSheet`（唯一模态容器）。

**状态矩阵（所有交互组件必须实现，缺一即走查不通过）**

| 状态 | 视觉 |
|---|---|
| default | 令牌原值 |
| hover | `surface2` 底 / 边框 `line2`（桌面鼠标必须有 hover，手机版可无） |
| selected | `accentBrand` 2.5 dp 边框 + `accentWash` 底 |
| dragTarget | 1.5 dp 虚线 `accentBrand` + `accentWash` 底 |
| disabled | 60% 不透明 + tooltip 说明原因 |
| focusVisible | 2 dp `accentFill` 外描边 + 2 dp 偏移（键盘可达性） |

### 5.3 AppState → UI 映射（衔接层，防止 UI 自己算业务）

| UI 元素 | 字段 | 禁止行为 |
|---|---|---|
| 导出按钮可用性 | `state.canExport` | 不重算"有没有输出目录" |
| 事件卡照片数 | `eventPhotoIds[id]` | 不用 `photos` 自行过滤 |
| 未匹配池 | `unmatchedPhotoIds` / `unmatchedPhotos` | 不自己扣减 |
| 进度条 | `progress.fraction` | 不算百分比 |
| 提示条 | `message` → 展示后 `clearMessage()` | 不保留已消费消息 |
| 错误 | `error` | 不吞、不改写文案 |
| 时间显示 | `captureTimeMs` + `AppZone.ID` | 不用系统时区 |
| 台账预览 | `ledger` 行 | 不重新拼文件夹名 |

## 六、交互规范

### 6.1 选择模型（中栏网格）

| 操作 | 行为 |
|---|---|
| 单击 | 选中单张，替换原选择 |
| Ctrl+单击 | 切换该张 |
| Shift+单击 | 从锚点到该张的连续区间 |
| Ctrl+A | 全选当前可见集合（事件内 / 未匹配池内，不跨区） |
| 空白处点击 | 清空选择 |
| 框选拖拽 | P1 再做（与拖拽移动冲突，需要修饰键区分） |

### 6.2 拖拽

| 从 | 到 | 结果 | 核心调用 |
|---|---|---|---|
| 中栏照片 | 右栏事件卡 | 移入该事件 | `movePhotos(ids, eventId)` |
| 中栏照片 | 未匹配池 | 移出事件 | `movePhotos(ids, null)` |
| 资源管理器 | 左栏源目录区 | 添加源目录 | `updateSettings` |
| `.txt` 文件 | 左栏日志区 | 导入日志 | `readLogFile` + `setLogText` |

拖拽必须给三种反馈：起点（半透明拖影 + 数量徽章）、路径（目标悬停高亮）、终点（落点卡片闪一次 6% `accentWash`）。

### 6.3 快捷键（首版）

| 键 | 动作 | 备注 |
|---|---|---|
| `Ctrl+O` | 添加源目录 | 打开原生文件夹选择 |
| `Ctrl+L` | 导入日志文件 | |
| `F5` | 重新分析 | `analyze()`，幂等 |
| `Ctrl+E` | 导出 | 等价于点主按钮 |
| `Ctrl+F` | 搜索事件/桩号 | 聚焦搜索框，不弹窗 |
| `Space` / 双击 | 大图预览 | |
| `←/→` | 预览内切换 | |
| `Esc` | 关预览 → 关 Sheet → 清选择 | 逐层退出，不一次全关 |
| `Delete` | 移入未匹配池 | **不删文件**，只改分类 |

> **没有 `Ctrl+Z`**：核心只提供 `resetManualAdjustments()`（全局恢复最初分类），没有撤销栈。
> 所以 UI 必须：① 移动后给 5 秒内可点的「撤销这一步」（本地记录逆操作，调 `movePhotos` 放回）；
> ② 全局复位按钮要二次确认。**不要画一个做不到的快捷键**。

### 6.4 反馈时机

| 场景 | 反馈 | 时长 |
|---|---|---|
| 分析/导出进行中 | 进度条 + 状态栏阶段名 + 主按钮转"取消" | 持续 |
| 单次操作成功 | 状态栏文字，不弹 toast | 3s 后淡出 |
| 业务失败（导出不完整） | Sheet + 失败明细，不自动关 | 需用户关闭 |
| 参数错误（如未设输出目录） | **前置禁用 + tooltip**，不做事后报错 | 常驻 |
| 拖拽落点 | 目标卡闪一次 | 180ms |

## 七、响应式与适配

### 7.1 宽度档（见 §4.2）

切换必须有明确阈值和明确行为，**不允许连续渐变**（渐变会让布局在某几个宽度上"半塌"）。
每档切换点都有单测：`WorkspaceLayoutTest` 覆盖 700–3840 每 7 dp 的总宽守恒与中栏下限。

### 7.2 DPI 档

| 缩放 | 验证要求 |
|---|---|
| 100% | 全程可用，文字不糊 |
| **125%** | **主力机型档，必须实测**（1366×768 内业机） |
| 150% | 三栏宽度按 dp 不变，视觉元素等比放大 |
| 175% / 200% | 不要求专门优化，但不得错位（自动通过 dp 换算保证） |

### 7.3 高度档

| 窗高 | 行为 |
|---|---|
| ≥700 | 状态栏显示完整计数（`匹配 x/y 无 GPS n HEIC n`） |
| 540~699 | 状态栏只显示状态文字，计数移到顶栏 |
| <540 | 不允许（AWT `minimumSize` 已锁） |

### 7.4 文字缩放

首版**不跟随系统文字缩放**（Compose Desktop 无此机制）。若 M6b 确认有需求，
只提供"紧凑/标准/宽松"三档字号令牌切换，不做自由缩放 —— 自由缩放会把 12sp 的中文压到不可读。

## 八、与现有功能的衔接

### 8.1 与 Android 版的一致性边界

| 项 | 是否与 Android 一致 | 说明 |
|---|---|---|
| 导出台账结构 | **必须一致** | 同一批数据两端产物可互认，列序/列名/内嵌照片尺寸不变 |
| 术语与文案 | **必须一致** | 事件类型、桩号格式、`99_未分类`、去重三态叫法与手机端一字不差 |
| 色彩与排版 | 同源但绝对值不同 | 同一套令牌，桌面字号 +1~2sp |
| 布局 | **不同** | 手机单列 + 步骤轨；桌面三栏常驻 |
| 交互 | 部分不同 | 桌面有 hover/右键/多选/快捷键；无长按 |

### 8.2 与核心的边界（UI 不能越界的事）

- 不自己算分类、不自己判重复、不自己拼文件夹名 —— 全在 `:core`。
- 不直接读文件系统做业务判断（除了缩略图/预览这类纯展示解码）。
- 不持有 `BufferedImage` 长生命周期（U1.3 的 `PcThumbnailProvider` 给的是受控句柄 + LRU + 内存上限）。
- 不弹系统对话框做业务确认（除文件选择器），统一走 `AppSheet`。

## 十、交付形式与适用范围

### 10.1 交付四件套（以及为什么不是 Figma）

| # | 产物 | 位置 | 权威性 |
|---|---|---|---|
| 1 | **设计令牌（代码）** | `desktop/ui/design/Tokens.kt` + `Theme.kt` | **最高**。色值/间距/字号只在这里改，文档只是说明 |
| 2 | **布局规则（纯函数 + 单测）** | `ui/layout/WorkspaceLayout.kt`、`ui/window/WindowGeometry.kt` | **最高**。三栏宽度、列数、窗口夹取都在这，22 条单测锁死 |
| 3 | **本规范文档** | `docs/WINDOWS-DESKTOP-UI-SPEC.md` | 决策与理由的唯一出处 |
| 4 | **可运行原型 + 走查证据** | `--demo` 运行 + `--shot` 截图 + `--log-file` 日志 | 验收依据。截图在 `desktop/ui/build/shots/` |

> **为什么不出 Figma 稿**：① 单人开发，矢量稿会在一周内与代码脱节，最终变成第三份"事实来源"；
> ② 本项目的布局变量是"窗宽/DPI/列数"这类**参数化**的东西，图能画 3 张，画不出 14 种组合；
> ③ 令牌已经是代码，改一个值所有界面同步，比改图快。
> 如果将来有专职设计加入，导出 `Tokens.kt` 为 design-token JSON 再导入 Figma 变量即可，反向亦通。
