# Photo-Mgm Windows 桌面版 · 开发计划（v1.0）

> 编制日期：2026-10-31　依据：`docs/WINDOWS-DESKTOP-PLAN.md`（技术方案 v1.1，commit `2f7fba8`）
> 性质：**待批准的执行计划**。批准前不执行 M0、不创建 `desktop/`、不改动 `algorithm/ data/ app/`。
> 排期基准：假设 **T0 = 2026-11-02（周一）批准并开工**，单人串行开发 + 用户节点验收。

---

## 一、开发目标

### 1.1 业务目标

让内业岗在 **Windows 电脑上**完成「巡查日志导入 → 照片自动归类 → 人工校正 → 交付台账 + 分类照片目录」全流程，摆脱手机小屏操作与 SAF 授权限制，且交付物结构与现有 Android 版完全一致（同一批数据两端产物可互认）。

### 1.2 技术目标

| # | 目标 | 量化判据 |
|---|---|---|
| G-1 | 算法核心零重写 | `algorithm` 17 个主文件 0 改动、290 用例在桌面构建内全绿 |
| G-2 | 平台适配层全替换 | 5 个平台接口（目录扫描/EXIF/哈希/缩略图/导出）均有桌面实现并有单测 |
| G-3 | 导出产物符合契约 | `§4.5` 六条契约逐条有对应单测，台账照片列前缀逐行等于实际文件夹名 |
| G-4 | 双端结果一致 | 同批样例：台账差异 0 行；照片归类结果一致 |
| G-5 | 符合 Windows 软件标准 | MSI 安装 →「程序和功能」可卸载 → 开始菜单/桌面快捷方式 → 无控制台黑窗 |
| G-6 | 不污染原工程 | 全程 `git diff` 对 `algorithm/ data/ app/` 为空 |

### 1.3 成功判据（验收线，来自方案 §2.5）

300 张端到端 ≤120s；1000 张导出成功率 ≥99.5%；台账与目录一致性 100%；双端台账差异 0 行；Win10/11 x64 干净环境安装成功率 100%。

1. **分支**：`docs/desktop-plan-v1.1`（已建）→ `docs/desktop-dev-plan`（本文件）→ 各自 PR 到 `main`，只触发 static-guards；合入后再开 `feat/desktop-m1-skeleton`，此后**每里程碑一个分支**，命名 `feat/desktop-m<N>-<slug>`。
2. **提交粒度**：一个任务 ID 一个 commit，message 前缀 `feat(desktop)/test(desktop)/fix(desktop)/docs(desktop)`，正文引用任务 ID。
3. **不可越界**：`algorithm/ data/ app/` 只读；确需改动核心时**停下来问**，不自行修改。
4. **不跨里程碑预支**：M4 未验收不进 M5；发现前序缺陷先修再前进，不做「先欠着」。
5. **阶段报告格式**（每个里程碑结束提交给你）：

```
### M<N> 完成报告
- 已完成：<任务 ID 列表 + 一句话结果>
- 产出文件：<新增/修改路径清单，含行数>
- 验证命令与结果：<命令原文 + 关键输出>
- 未解决 / 需你决策：<逐条，含建议默认值>
- 下一步：M<N+1> 的首个任务与预计产出
```
